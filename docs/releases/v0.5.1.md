## Summary

DockGuard now verifies both managed targets and every visible process holding the external drive
before it says the drive is safe to eject.

## Fixes

- The dashboard names process holders such as `zsh (PID 23721, using drive)` alongside managed
  target blockers.
- A failed or timed-out holder scan produces unknown readiness instead of a safe claim.
- Eject commands refuse before `diskutil` when a holder is known, while preserving the later scan
  that diagnoses a process opening the drive during eject.
- The dashboard releases its own inherited working directory on the external drive; the parent
  shell remains visible until the user runs `cd` elsewhere.

## Validation

- Full Go suite and race-enabled suite pass.
- `go vet ./...` passes.
- Live dashboard check on the configured T7 names the shell whose current directory is on the
  drive while retaining managed target blockers.
- The live holder query completed in 0.14 seconds, within the two-second timeout and three-second
  dashboard refresh budget.

## Compatibility

No config or command syntax changes. `list`, `status`, and stop without `--eject` keep their
existing behaviour.
