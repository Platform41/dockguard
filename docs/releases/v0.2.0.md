## Summary
- DockGuard now manages a list of targets instead of a single Docker Desktop setup. This release supports Docker Desktop; Xcode, PostgreSQL clusters and Apple `container` stacks follow in v0.3.0 and v0.4.0 (`docs/specs/multi-target.md`).
- Added `dockguard list` to show every managed target and its state.
- `stop --eject` now ejects only when every target is confirmed stopped.

## Highlights
- New command: `dockguard list` (running, partial, stopped or unknown, per target)
- Optional target on `check`, `start` and `stop`; without one they act on `docker`
- Config lookup adds `~/.config/dockguard/dockguard.yaml`, so `--config` is no longer needed there
- New check: the Docker storage path must be on the drive, following symlinks the way the filesystem does
- Config parsed with `yaml.v3`; unknown keys and kinds are reported with the target and key

## Behaviour changes
- `status` covers every target. A running target counts as ready; a target whose state can't be read does not.
- A missing config file is an error that names the paths tried, instead of a silent fallback to built-in defaults.
- `stop --eject` re-checks every target after stopping (waiting up to 30 seconds for the one just stopped) and refuses to eject while any target is running, partly running or unknown. There is no override flag.
- Checks that depend on the drive show `[skip]` when the drive isn't mounted.

## Upgrading
- v0.1 config files keep working as a single `docker` target; `status` prints a one-line suggestion to move to the new format in `examples/dockguard.yaml`.
- If you relied on built-in defaults without a config file, create `~/.config/dockguard/dockguard.yaml`.

## Notes
- Requires Go 1.23+ to build from source.
