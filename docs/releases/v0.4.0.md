## Summary
- DockGuard now manages Apple `container` stacks, completing the four target kinds planned in `docs/specs/multi-target.md`: Docker Desktop, GUI apps, PostgreSQL clusters and container stacks.
- One command takes everything off the drive: `dockguard stop --all --eject`.
- When macOS still refuses an eject, DockGuard names the processes holding the drive.

## Highlights
- New `container` kind: your own `up` and `down` scripts start and stop the stack, and state comes from `container list` (`running`, `partial` or `stopped`).
- New `stop_system` option (D-017): also stops Apple container's system service, which keeps files open on the drive after a stack stops. DockGuard refuses to stop it, naming them, while containers outside the stack are running.
- New `dockguard stop --all [--eject]`: stops everything in reverse config order, carries on past failures, stops shared container systems last, and ejects only when every target is confirmed stopped.
- Busy ejects name the culprit, for example `still using the drive: Google Chrome (PID 33061)`.

## Behaviour changes
- Container state only counts as stopped when DockGuard can confirm it: the container system reports `unregistered`, or `container list` shows the stack's containers stopped. A daemon failing its health check, or output DockGuard can't read, is `unknown`, which blocks the eject.

## Upgrading
- Add each container stack to your config as a `container` target (see `examples/dockguard.yaml`). Set `stop_system: true` if nothing else on the machine needs Apple container's system service while the drive is ejected.
- If a launchd agent starts a stack at login, remove it and start the stack with `dockguard start <stack>` instead (D-014), so it never starts while the drive is missing:
  ```bash
  launchctl bootout gui/$(id -u)/<agent-label>
  mv ~/Library/LaunchAgents/<agent-label>.plist <somewhere-outside-LaunchAgents>
  ```

## Notes
- macOS loads every app's share extensions to draw the Share menu, so an app installed on the drive (such as Xcode) can have files held by unrelated apps like a browser. The busy-eject message will name them.
