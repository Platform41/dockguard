## Summary

DockGuard now trusts a registered drive, not just a path, can remount it in one step, can report
and update its own version, and shows container stacks' persistent volumes (D-021, D-022, D-023).

## Added

- **Registered drive identity (D-021).** Optional `drive_uuid`: with it set, the drive counts as
  mounted only when that exact volume is mounted at `drive`. DockGuard reports `not mounted`,
  `not connected`, `mounted elsewhere`, `wrong volume`, `stray folder` and `unknown` with a reason,
  treats all of them as not mounted, and refuses to eject a volume it hasn't verified. Configs
  without `drive_uuid` behave as before, with a one-line hint to register.
- **`dockguard drive`** (read-only) prints the mounted volume's identity and the `drive_uuid:` line
  to add. **`dockguard mount`** mounts the registered drive by UUID within 90 seconds and confirms
  it landed at the configured path. The dashboard offers **`m`** when the registered drive is
  attached but unmounted.
- **`dockguard version` (D-023)** prints the build's version, checks the latest release through the
  Go toolchain (only in this command, isolated from any surrounding Go module), and in a terminal
  offers `Update to vX? [y/N]`. Answering `y` runs a pinned `go install`; DockGuard reports
  `Updated` only when the installed file reports that version.
- **Persistent volumes on container targets (D-022).** Optional `volumes` shows each named volume
  as a `list` sub-row and a `status` line, with its allocated size read from disk. Information
  only: lifecycle, dashboard and eject are unchanged.

## Validation

- Full Go suite (383 tests) and race-enabled suite pass on merged `master`; `go vet` passes.
- Read-only checks on real disks: every drive status, including a stray folder and a wrong volume;
  `dockguard drive` registered and unregistered; `dockguard mount` refusing a stray folder.
- The update flow end to end into a scratch `GOBIN`: a pre-v0.6.0 build offered v0.6.0, `n` left it
  untouched, `y` installed and verified it.
- Volumes against the real `fizzy-mysql` volume: `present, 281 MB` (allocated, not the 512 GiB
  sparse size), `missing` for an absent volume, no `container volume` calls.
- Maintainer live checks on the T7 with a build of merged `master` from the main checkout, all
  passed: `dockguard drive` before and after registering `drive_uuid`; the
  `registered drive at mount path` check in `status`; `fizzy-mysql` shown under `fizzy` with the
  container system running and stopped; `stop --all --eject`, then `dockguard mount` remounting at
  `/Volumes/T7SSD`; dashboard eject followed by `m`.

## Compatibility

New optional keys (`drive_uuid`, `volumes`) and new commands (`drive`, `mount`, `version`) only.
Configs without them behave as in v0.6.0. `dockguard version` is the only command that uses the
network, and only through the `go` command.
